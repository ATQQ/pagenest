实测配色审计 · 2026-10-22

文档站和阅读站的配色，其实是一套工业配方

我用 Playwright 逐个打开了 21 个主流站点，抓的是渲染后真实生效的计算色（含透明层叠合成）， 不是官方设计稿里的色板。结果指向一个反直觉的结论：这些站点让你眼睛累， 不是因为对比度不够，而是因为对比度过头、底色过亮、链接过艳三件事同时发生。

采样：22 个页面 · 12 类文档站 + 10 类阅读站 · 视口 1440×900 · 深色模式未计入

12 / 22 个站点的正文底色是纯白 #ffffff（Lab L*=100），在亮环境下整屏反射白光
21 : 1 GitHub Docs 与 Kindle Cloud Reader 的正反对比度上限，远高于长文阅读的舒适区间
C* = 127 Astro Docs 链接色的 Lab 彩度，饱和纯蓝在整页重复出现，是最强的一处视线干扰

工业配方的四个特征

所有主流站点都在做同一件事：把底色压到最亮、把文字压到最黑、把链接推到最艳，再把字号缩到 14px。这套组合在「扫读」时效率最高，在「通读」时最伤眼睛。

底色：能有多白就多白

01

12 个文档站里 7 个直接用 #ffffff，其余用 #fafafa。实测 Lab 彩度全部落在 0–2，也就是完全不带任何颜色倾向——把中性灰当成「不偏色」，代价是屏幕变成一块发光的白板。

唯一例外：Anthropic Docs 用 #faf9f5 暖白底

对比度：两个极端都有人站

02

高端在 21:1（GitHub、Kindle、少数派文章页），低端在 1.9:1（番茄小说首页，#b3b3b3 配 #f6f6f6）。中间地带 7–15:1 反而只有 Stripe、MDN、Next.js 少数几家。

2.88 : 1 — 掘金正文  ·  4.42 : 1 — 语雀正文

链接：全部挤在蓝紫区间

03

12 个文档站的链接色相几乎全落在 268°–306° 这一段蓝紫区，彩度 42–127。饱和蓝在纯白底上对比极强，一页十几条链接就把视线来回拽——「可点击」的约定反而变成了阅读噪音。

字号：文档站比阅读站还小

04

文档站正文集中在 12–16px，行高 19–30px。GitHub 文档只有 14px/21px。阅读类站点反而宽松：番茄小说正文页 14px/21px，豆瓣 13px/21px，但底色要么纯白要么纯黑。

同一段文字，三种配方

下面三块用的是同一段中文正文，套用三种真实存在的配色。前两块是行业里最常见的配置，第三块是按上面的结论调出来的。

关键差别不在颜色本身，而在「重复次数」。 蓝紫链接之所以累，是因为它在一页里出现十几次，每次都是一次高对比的事件； 而暖白底 + 低彩度墨色之所以舒服，是因为整页只有一次对比事件，其余全是安静的灰阶。

pagenest 改版前后

同一套算法量 pagenest 的 8 套主题。改版前它的对比度就是全场最优的一档，说明问题从来不在对比度；这一版把彩度、渐变和链接形态一起收进了舒适区。

主题阅读底色正文链接 正文对比底彩度 C* 链接彩度 C*判定
改版前 → 改版后（已落地）：
① 正文对比度 10.7–16.5 收窄到 10.4–14.3，把 21:1 那种"纯黑白"配方拉出舒适区；
② sepia 底色彩度 C* 从 12 压到 8，paper 从 3.2 降到 3.7 以下并保持暖调；
③ 链接彩度统一压到 C* ≤ 30（原来最高 54），并给正文链接补上下划线 —— 让「可点击」靠形状传达，而不是靠高彩度色块；
④ 去掉 body 上的顶光渐变，页面上下亮度一致，眼睛不需要持续重新适应；
⑤ amoled 保留纯黑底，但正文从 #c8c8ca 压到 #b6b6ba，减少深色底上的光晕。

改版落地的取值

按上面的阈值重算后的三套代表取值，已写进 src/client/styles/global.css 的 8 套主题里。全部满足：正文对比 7–15:1、底彩度 ≤ 8、链接彩度 ≤ 30，且链接对比仍 ≥ 4.5:1。

已落地的改动：去掉 body 的顶光渐变 → 压低 sepia / 各主题底色彩度 → 统一把链接彩度降到 C* ≤ 30 并补下划线 → 夜间三套主题把正文压暗一档。改动集中在 src/client/styles/global.css 与 src/client/App.module.css。 单测、类型检查、lint 与 e2e（含代码块与源码区对比度断言）全部通过。
方法说明。 用 Playwright + Chromium 逐站加载，等 DOM 与字体稳定后读取渲染后的计算样式：背景色沿 DOM 树逐层做 alpha 合成，避免透明容器取到假黑； 正文取「可见、字号 14–22px、文本长度 > 80 字符」的最长段落；对比度按 WCAG 相对亮度公式计算，彩度按 CIE Lab 的 C* 计算；另对首屏截图做像素采样交叉验证。

局限。 Stack Overflow 有反爬拦截，未取到；Tailwind Docs 正文色取自导航与列表区域，未能定位文章段落；Apple Books 无网页阅读器；微信读书、Kindle 阅读页部分内容在 iframe / 登录墙后，只取到外层底色； 所有数据均为浅色模式下的实测值，深色模式未纳入。

阈值说明。 4.5 : 1 是 WCAG 2.2 对正文的硬性下限；「7–15 : 1 舒适区」「底彩度 ≤ 8」「链接彩度 ≤ 30」是本次分析采用的设计经验阈值，用于横向比较这些站点，不是医学结论。
